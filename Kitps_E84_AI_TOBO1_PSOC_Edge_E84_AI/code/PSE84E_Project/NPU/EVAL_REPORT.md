# 人体/背景二分类模型精度评估报告

日期：2026-11-03　评估脚本：[eval_human_model.py](eval_human_model.py)　嵌入式工程、`output/` 下的模型均未改动。

> 这份前半部分评估的是 v1 模型。`output/` 和 CM55 工程现在已换成 v2，v1 产物保留为 `*_v1`，改进结果见文末“v2 训练改进”。

## 结论

1. **量化和 int8 I/O 转换都没有掉点。** float（`model.h5`）、uint8 I/O（`model_quantized.tflite`）、int8 I/O（`model_quantized_int8io.tflite`，与提交 05e95e0 中送进 coretools 的文件 git hash 一致）三者在全部 496 张图上的 argmax 完全一致（100%）。uint8io 与 int8io 的输出逐位相同；float 与量化版的 p_human 最大差 0.06。
2. **类别顺序没有反。** 下标 0 = background，1 = human，与训练脚本、`inference_task.h` 一致。对调下标后验证集准确率会从 90% 变成 10%。
3. **CM55 端预处理与训练基本一致。** 灰度公式、int8 零点和缩放系数、类别下标都正确；缩放方法不同（板端 2×2 盒式平均，训练用 LANCZOS），但只带来 0.6 个百分点的差异（见下文）。
4. **主要问题在模型和数据本身。**
   - 训练集只有 496 张，**看起来是按提示词 AI 生成的竞赛场馆图片**（`infer_image_train/promt.txt`），原图已经是灰度，1448×1086。不是 OV7675 实拍。
   - 训练脚本按图片随机划分 80/20，训练集和验证集来自同样 16 个场景，验证集还被用来挑 checkpoint，所以 90% 的验证准确率本身就偏乐观。
   - 按场景留出交叉验证（训练时完全没见过测试场景）的结果：**准确率 82.5%，误报率 29.0%，漏检率 11.3%**（4 折合并，n=496）。各折准确率都只有 81–83%，误报率 14–41%。另外，原训练配置有 3/8 次训练"塌缩"成全判 human：EarlyStopping 看 `val_accuracy`、patience 15，模型在多数类准确率上停滞 15 个 epoch 后就被提前停掉。现有的 `output/model.h5` 是一次运气较好的训练结果。
   - 换到真实摄像头画面后，域差异只会让精度进一步下降。接入会话用 3 张样例图测试错 2 张，与此一致。

**结论：距离开题指标（准确率 ≥95%、误报率 ≤5%）还差得远，原因是模型和数据，不是量化、类别顺序或预处理。必须用 OV7675 实拍数据重新训练和评估。**

## 训练脚本要点（train_npu_model.py）

- 预处理：`Image.open().convert('L').resize((160,120), LANCZOS)`，uint8 直接送入模型，模型第一层 `Rescaling(1/127.5, -1)`。量化后输入 scale 1.0，uint8 版 zp 0，int8 版 zp -128。也就是说 `q_int8 = gray - 128`。
- 类别：`person/` → 1 (human)，`scene/` → 0 (background)，`CLASS_NAMES = ['background','human']`。
- 划分：`np.random.seed(42)` 打乱后前 80% 训练（396 张）、后 20% 验证（100 张：human 64，background 36）。没有独立测试集。EarlyStopping 和 ModelCheckpoint 都看 `val_accuracy`。
- 量化：代表数据集取训练集前 100 张，全整数 INT8，I/O 为 uint8。

## 结果

混淆矩阵记为 `[[TN, FP], [FN, TP]]`，行是真值（background、human），列是预测。误报率 FPR = FP/(TN+FP)，即背景被判成人的比例；FNR 是漏检率。

"塌缩"指训练集上只输出一个类别。第 1 次尝试使用与训练脚本完全相同的回调；塌缩后换随机种子重训，并把 EarlyStopping 推迟到第 30 个 epoch 之后（`start_from_epoch=30`），最多重试 3 次。如果不重试，塌缩的两折会全判 human，合并准确率降到 73.2%，误报率 68.8%。

即使测试的是同一类场馆、同一种 AI 生成风格的图片，只要场景没在训练中出现过，误报率就达到约 29%，远高于开题要求的 ≤5%。之前 90% 的验证准确率主要靠"见过这个场景"。训练脚本建议：EarlyStopping 改成监控 `val_loss` 或设置 `start_from_epoch`，并加上 BatchNorm 或数据增强来稳定训练。

## CM55 端 inference_task.c 核对（分支 claude/brave-zhukovsky-7cf13b，05e95e0）

| 项 | 训练 | CM55 端 | 结论 |
| --- | --- | --- | --- |
| 灰度公式 | PIL `L = 0.299R+0.587G+0.114B` | `(306r+601g+117b)>>10`，与 299/587/114 等价 | ✅ 一致 |
| 输入量化 | int8 版 scale 1.0，zp -128 | `gray + INPUT_ZERO_POINT(-128)` | ✅ 一致（与 coretools `q_param.txt` 吻合） |
| 输出反量化 | scale 1/256，zp -128 | 运行时读取 `model_obj->output_scale/zero_point` | ✅ 一致 |
| 类别下标 | 0 background，1 human | `CLASS_BACKGROUND 0`，`CLASS_HUMAN 1` | ✅ 一致 |
| 缩放 | 原图 → 160×120，LANCZOS | 320×240 → 160×120，2×2 盒式平均 | ⚠️ 不同，实测影响 ≤0.6 个百分点 |
| 位深 | 8 位灰度 | RGB565 截位后直接用（R/B 最大 248，G 最大 252） | ⚠️ 平均偏暗约 2.3 级，影响很小 |
| 颜色顺序 | — | 假设 BGR565，R 在 bit15:11 | ❓ 无法用灰度数据集验证，需上板确认 |

嵌入式代码**不需要为精度而改**。以下是可选的对齐改进，不影响本次结论：

- 消除截位偏暗：把高位复制到低位，`r = ((px>>8)&0xF8) | (px>>13)`，`g = ((px>>3)&0xFC) | ((px>>9)&0x03)`，`b = ((px<<3)&0xF8) | ((px>>2)&0x07)`。
- 更好的做法是**让训练端去对齐板端**：在训练脚本里把预处理改成"缩放到 320×240 → 2×2 平均"，或者直接用板端导出的 160×120 int8 帧来训练，这样板端代码完全不用动。
- 判定逻辑里 `class_id` 用的是 `conf_human > conf_background`，`human_present` 用的是 `conf_human >= 0.5`。p 恰好等于 0.5 时两者会不一致（q=0 时），属于边界情况，可以统一成同一个条件。
- 上板后核对颜色顺序：把 `model_input` 通过 UART 导出，与同一帧在 PC 上用 PIL 转出的灰度图对比。如果人脸、皮肤偏暗而蓝色物体偏亮，说明 R/B 接反了。

## 下一步建议

1. **用 OV7675 实拍数据重做数据集**（方案见下）。现有 AI 生成图可以作为补充，不应再作为主体。
2. **按场景或采集批次划分 train/val/test**，测试集必须来自训练时完全没出现过的场景或时段。开题指标只用测试集来报告。
3. 训练数据从板端采集：在 CM55 上把 `preprocess_bgr565_to_gray_i8()` 的输出（或原始 320×240 BGR565 帧）通过 UART/SD 卡导出，保证训练与部署的像素流水线逐位一致。
4. 加数据增强（亮度/对比度、水平翻转、小幅平移缩放、高斯噪声），background 类要补足到与 human 相当的数量。
5. 重新评估时直接运行 `python eval_human_model.py --dataset <新数据集>`（目录结构为 `场景*/person`、`场景*/scene`），加 `--cv 4` 得到按场景留出的估计。

## OV7675 实拍补充数据采集方案

目标：每类 ≥1500 张，总计 ≥3000 张。测试集单独采集 ≥300 张/类，使用训练时没出现过的场地或日期。

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 场景 | ≥8 个：实验室、走廊、教室、宿舍、比赛赛道（实物或仿真场地）、室外楼前、车库/地下、杂物堆放处 | 每个场景 human 和 background 都要采，且使用同样的机位，这样模型才能学"有没有人"，而不是学"是哪个场景" |
| 距离 | 0.5 m、1 m、2 m、4 m、6 m、8–10 m | 对应雷达 0.2–10 m 的工作范围。远距离（人占画面 <10%）是当前漏检最多的情况，要多采 |
| 姿态 | 站、走、跑、蹲、坐、侧身、背对、半身出画、多人（2–3 人）、手持物品 | 当前错例集中在远处小人物、蹲姿和头部出画 |
| 光照 | 白天自然光、日光灯、昏暗（只开一半灯）、逆光（窗前）、夜间室外路灯 | OV7675 的自动曝光在暗光下噪声很大，必须覆盖 |
| 人员 | ≥10 人，不同服装颜色（尤其是黑、白、与背景同色）、性别、身高 | |
| background 难例 | 人形立牌、衣架挂衣、椅子堆、海报上的人像、显示器上的人像、窗帘、植物 | 专门压误报率 |
| 每类张数 | 每个场景 × 每个距离档约 30 张 human、30 张 background（不同光照、姿态各采几张） | 8 场景 × 6 距离 × 30 ≈ 1440 张/类，再加难例 |
| 采集方式 | 板端以 1–2 fps 抽帧，导出 320×240 BGR565 原始帧和 160×120 灰度帧，文件名带场景、距离、光照、日期 | 相邻帧几乎相同，抽帧间隔不要太短，同一段视频里的帧不能同时进入 train 和 test |
| 标注 | 人体可见面积 ≥30% 的帧标 human；只露出很小一部分（<10%）的帧要么单独标注，要么剔除 | 标准要写进 README，避免标注不一致 |

### 结论

- **在“没见过的场景”上，准确率从约 85.8% 提到约 92.5%，误报率从约 20.8% 降到约 7.6%（INT8，阈值 0.5）。** 训练塌缩从 3 次评估共 13 次降到 0 次。
- **把阈值取 0.60 时：准确率 92.1%，误报率 5.5%，漏检率 9.3%。** 误报率接近开题要求的 ≤5%，准确率离 ≥95% 还差约 3 个百分点。
- **两项开题指标都还没有达到。** 这些数字也只代表 AI 生成的同类场馆图，**不代表 OV7675 实拍效果**，上板效果未知，真实数据仍然必须采集。
- **当前工程的阈值仍是 0.5，整机按 0.5 档运行。** 改成 0.6 要 84E 和 H7 两边一起改（见“阈值”一节），这次按约束没有改。

| `v1` | 原网络和原训练方式 | 3 | 85.8 | 20.8 | 10.5 | 基线 |
| `stab` | 训练稳定性（见下） | 3 | 92.3 | 9.7 | 6.6 | **保留，提升最大** |
| `stab_scale` | `stab` + 缩小补边 | 1 | 91.1 | 10.2 | 8.1 | 保留（只跑 1 次，单看无明显提升，与下一行一起用） |
| `stab_bg` | `stab_scale` + 背景图大幅裁剪 | 3 + 3 | 94.2（复测 92.5） | 5.7（复测 7.2） | 5.8（复测 7.6） | **最终采用** |
| `cam_lite` | `stab` + 40% 样本做摄像头仿真 | 3 | 92.5 | 7.8 | 7.3 | 未采用（与 `stab` 差别在波动内） |
| `bg_lite` | `stab_bg` + 40% 样本做摄像头仿真 | 3 | 92.2 | 8.7 | 7.3 | 未采用，**但作为上板后的备选** |
| `cam_scale` | `stab_scale` + 85% 样本做摄像头仿真 | 3 | 90.5 | 11.2 | 8.6 | 放弃 |
| `cam` | `stab` + 85% 样本做摄像头仿真 | 1 | 85.7 | 21.6 | 10.3 | 放弃 |
| `full` | `cam_scale` + 背景裁剪 | 1 | 86.3 | 22.2 | 9.1 | 放弃 |
| `full_w15` | `full`，网络加宽 1.5 倍（256 KB） | 1 | 88.9 | 15.3 | 8.8 | 放弃，说明容量不是主要瓶颈 |

`stab` 的内容是打包一起测试的，**没有逐项拆开**，说不清其中哪一项贡献最大：BatchNorm；human 和 background 各占一半的均衡采样；label smoothing 0.05；按 `val_loss` 早停且前 10 轮不停；按场景划分验证集；水平翻转和小幅旋转平移；所有训练图都走板端预处理链。这组改动的 22 组实验、共 88 次训练都没有塌缩。

**对摄像头仿真要谨慎看待：** 这项增强（亮度、gamma、暗光噪声、模糊、运动模糊、暗角、JPEG）在这里没有得分，但这不能证明它没用。测试图全是干净的 AI 图，本来就测不出抗噪声和抗暗光的能力。反过来，**最终模型没有用这项增强，在暗光和噪声画面上可能明显变差。** 所以 `bg_lite` 留作备选：如果实拍发现暗光或噪声下表现差，就换它训练，命令里的配置名换掉即可。

没有做的项：

- **迁移学习（MobileNet）**：本机没有 ImageNet 权重，要先下载；常见配置也容易超过 300 KB。这次没有尝试。
- **人工合成难例、拼接背景**：数据集没有人物框，也没有单独的难例集，从人物图裁背景有把人裁进去的风险。这次只对纯背景图做了裁剪放大。

### 阈值

下表是复测三次 INT8 模型的测试集平均值。

| 阈值 | 准确率 | 误报率 | 漏检率 | 说明 |
| --- | --- | --- | --- | --- |
| 0.3 | 92.1 | 12.9 | 5.2 | H7 以前用的值 |
| 0.5 | 92.5 | 7.6 | 7.5 | **工程现在的值** |
| **0.6** | **92.1** | **5.5** | **9.2** | **建议值** |
| 0.7 | 90.7 | 4.0 | 12.2 | 第一个平均误报率低于 5% 的档 |
| 0.8 | 89.2 | 2.5 | 15.3 | |
| 0.9 | 83.9 | 0.8 | 24.5 | |

0.60 是只看验证集选出来的（合并验证集得到 0.605，三次分别为 0.625、0.493、0.739），没有用测试集挑选，用 0.605 测得 92.1/5.5/9.3。分次差别较大，上板后还要用实拍数据重新定。

**阈值要两边一起改：**

- 整机判定在 H7：84E 把原始概率发给 H7，由 `code/STM32H7/Core/scheduler.c` 的 `RECOG_HUMAN_CONF`（提交 a32bb6b 起为 0.5）判断是不是人。84E 的 `HUMAN_CONF_THRESHOLD` 只决定屏幕上画不画框。
- 代码注释规定这两个值必须相同，否则 0.5～0.6 之间的画面会 84E 判背景、H7 却派摄像头去跟踪。
- 所以这次**没有改 `HUMAN_CONF_THRESHOLD`，两边都保持 0.5**，整机按上表 0.5 档运行，误报率约 7.6%。
- 想要 0.6 档的效果，需要把 `RECOG_HUMAN_CONF` 和 `HUMAN_CONF_THRESHOLD` 同时改成 0.6f。本次约束不改 `code/STM32H7`，所以留给项目负责人决定。也可以等实拍数据出来后一次定下来。

### 量化问题及修复

板端灰度因 RGB565 截位最大只有 250，如果校准图都走板端预处理，模型的输入缩放系数就可能不是 1.0，而 `inference_task.c` 写死了 `gray - 128`，只有系数正好是 1.0 才对。现在 `train_v2.py` 校准时固定加入全黑、全白两帧，并在系数不对时直接报错。复测和最终模型都在修复之后，选型阶段的 INT8 结果则在修复之前，所以上面的选型表只用 float 数字。

### 验证情况

已经做过：

- ML CoreTools 生成成功。
- 合并最新 main 后，cm33_s、cm33_ns、cm55 三个子工程完整编译通过（`make build`，在短路径副本 `%TEMP%\bv2` 中）。

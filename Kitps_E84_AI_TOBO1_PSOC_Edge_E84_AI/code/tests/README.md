# 电脑端自动化测试

不需要任何开发板，在电脑上用 gcc 编译**真实的固件源码**，只把硬件相关的部分（HAL 定时器、串口收发、雷达测量、日志）换成替身，用模拟数据检验逻辑是否正确。

## 运行

- Windows（MinGW gcc）：`powershell -ExecutionPolicy Bypass -File run_tests.ps1`
- Linux / macOS：`sh run_tests.sh`

全部通过时最后一行显示 `ALL TESTS PASSED`。**每次修改 H7、ESP32 或 84E 通信相关代码后都应先跑一遍。**

## 测了什么

| 程序 | 被测代码 | 内容 |
|---|---|---|
| `test_h7_demo_flow` | 调度器 + 真实雷达模块，测距、84E、ESP32 由“虚拟房间”替身计算 | 按答辩流程跑一遍：空房间学背景不报目标、发现并锁定、边界接力、人走远不算新目标、第二目标、遮挡复锁、椅子并入背景、STOP/START、RELEARN。同时生成 `build/demo_flow.log` 供监控界面回放 |
| `test_h7_scheduler` | H7 调度器、云台、目标列表、复锁、融合、预判、实验记录 | 13 个场景：单目标锁定（跟踪命令只发一次、辅助板只启动一次、三角定位正确）；辅助板丢失不影响主板；丢失后复锁成功；复锁失败释放；84E 连续判为非人体后并入背景；漏判一两次不会把人记成背景；人走近走远不算新目标；人体判定阈值与 84E 一致；通信统计定期输出；三个目标（第三个上报、有板空出后补上）；STOP/START；84E 超时；边界接力 |
| `test_h7_units` | 雷达距离图、超声波驱动、几何 | 模拟房间（墙、柜子、门口、±3 cm 噪声）的背景学习与人体检测；脉宽跨定时器周期的换算；超量程与超时；三角定位 |
| `test_esp32_tracker_0/1` | ESP32 跟踪器（三高特征区域 / 全图匹配） | 合成画面中移动目标的跟踪误差、强纹理背景、远处小目标、静止不抖动、遮挡后复锁；两种模式的单帧耗时对比（对比实验①） |
| `test_protocol` | H7、ESP32、84E 三方的帧打包与解析 | 四个方向的字段逐一核对；乱码与校验错误帧被丢弃；两块 ESP32 交错发送；超长文本截断 |

## 这些测试已经发现并修复的问题

- ESP32 帧解析少收一个字节，**H7 发出的所有命令都会被 ESP32 丢弃**
- H7 发往 ESP32 的文本帧缓冲区少一个字节，文本满 64 字节时越界、对方拒收
- ESP32 卡尔曼参数过度平滑，目标转向时输出滞后 3~4 px（已调参，误差约 2.6 px）
- ESP32 卡尔曼的帧间隔是函数内 static，各次跟踪互相影响

## 不能代替上板测试的部分

电机实际方向和速度、舵机滞后、真实摄像头画质与光照、超声波波束宽度、串口电平与时序，都必须在实物上验证。这里的阈值（如 `RADAR_CHANGE_CM`、`TRACK_MAD_MAX`）也只是在模拟数据上合理，需要上板整定。

`test_h7_demo_flow` 的 ESP32 替身每帧修正 30% 的偏差，比真实 PID 高约 20 倍，所以它测不出云台跟不跟得上。跟踪速度用 `tools/sim_wasm/test_live_sim.js` 看（真实 H7 固件 + 照抄 ESP32 控制量的模型），见 [说明](../tools/sim_wasm/README.md)。

## 替身说明

- `stubs/h7/`：STM32 HAL 的最小子集。被测的 `Core/*.c` 会先找到同目录的真实 `main.h`，所以编译时用 `-D__CORE_MAIN_H` 等预先定义保护宏让它们变空，再用 `-include stubs/h7/main.h` 注入替身。
- `stubs/h7_stubs.c`：记录调度器发出的 84E/ESP32 命令和实验事件，测试据此判断行为。
- `stubs/esp/`、`stubs/e84/`：ESP-IDF 与英飞凌 PDL 中通信代码用到的类型。ESP32 侧与 H7 同名的函数在编译时改名（见脚本中的 `ESP_RENAME`）。
- `e84_side.c` 直接 `#include` 84E 的 `h7_link.c`，以便调用其中的 static 函数。

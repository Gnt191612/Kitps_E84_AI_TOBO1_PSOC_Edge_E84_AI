# 实验数据采集与对比实验

本文说明如何采集开题报告第九节的指标，以及三组对比实验怎么做。代码已具备采集能力，但**尚未在实物上跑过**，下面的数据全部需要上板实测。

## 1. 接线

| 设备 | 引脚 | 说明 |
|---|---|---|
| H7 调试串口 UART4 | PC10 → USB-TTL 的 RX，GND 共地 | 921600 8N1，只发不收。H7 的全部日志和 `$E` 实验事件都从这里输出 |
| ESP32 控制台 | 板载 USB 串口（UART0） | 115200。`$T` 单帧耗时行从这里输出 |

H7 日志原先走 huart2，会混进 ESP32-A 的协议链路，现已改到 UART4。PC10/PC11 在第三方底板上是否空闲，需对照底板原理图确认。

## 2. 采集

1. 用串口工具（或 `python -m serial.tools.miniterm COMx 921600 > h7_run1.log`）记录 H7 的 UART4 输出；ESP32 控制台另存一份。
2. 按测试方案做实验（例如遮挡 30 次、横穿云台边界 30 次）。
3. 统计：

```
python code/tools/exp_stats.py h7_run1.log esp_a_run1.log
```

脚本输出 Markdown 表，可以直接贴进报告。多份日志会逐列对比。

## 3. 指标对应关系

| 开题报告指标 | 日志来源 | 统计项 |
|---|---|---|
| NPU 单帧推理时延 ≤50 ms | H7 `RES84E` | 命令→结果时延（含转台到位后的通信，略大于纯推理时间；纯推理时间应在 84E 端单独打点） |
| 发现→稳定锁定 ≤500 ms | H7 `CAND`/`LOCK` | 发现→锁定 |
| 跟丢后 3 s 内复锁 ≥80% | H7 `LOST`/`RELOCK` | 跟丢后3s内复锁 |
| 边界接力成功率 ≥90% | H7 `HOSTART`/`HOOK`/`HOFAIL` | 边界接力成功 |
| 视觉跟踪帧率 ≥25 fps | H7 `FPS` | ESP32 回传帧率 |
| 人体识别准确率/误报率 | 需带标签的独立测试集 | 不在本脚本内，见模型评估报告 |
| 雷达测距误差 | 卷尺标定 | 需单独记录 |
| 板间丢帧/校验错误率 | 尚未接入计数 | 待补：协议层 XOR 失败计数 |

## 4. 三组对比实验

每组编译两版固件，**只改一个开关**，在相同场景下各录一份日志后一起交给脚本。

| 对照 | 开关 | 位置 | 看哪些统计项 |
|---|---|---|---|
| ① 三高特征区域 vs 全图匹配 | `EXP_TRACK_FULL_FRAME` 0 / 1 | `ESP32_ov2640/algorithm/track_algorithm.h` | ESP32 单帧耗时、回传帧率、丢失帧占比 |
| ② 有 / 无历史波动预判扫描 | `EXP_PREDICTIVE_AIM` 1 / 0 | `STM32H7/Core/exp_config.h` | 84E 判为人体比例、跟丢后3s内复锁、复锁耗时 |
| ③ 双目互辅 vs 单目跟踪 | `EXP_ASSIST_ENABLE` 1 / 0 | `STM32H7/Core/exp_config.h` | 三角定位与雷达距离差、融合坐标（`FUSE`） |

对照③的"定位误差"需要真值：在地面标出若干已知位置让人站定，用 `FUSE` 坐标与真值比较。

## 5. 上板前必须确认的参数

- `STM32H7/config_mount.h`
  - `MOUNT_CAMx_PAN_OFFSET`：每台相机在 Pan=135° 时的实际朝向。代码现按此换算方位与云台角，边界接力也依赖两块 ESP32 朝向不同。若三台都朝前，全部改为 0。
  - `ESP32_IMG_X_BEARING_SIGN`：图像 x 增大对应方位角增大还是减小。
  - 各器件坐标：三角定位直接使用 ESP32-A/B 的位置。
- 舵机标定后的脉宽、`GIMBAL_PAN_135_MOVE_MS`（预判外推用到转台时间）。

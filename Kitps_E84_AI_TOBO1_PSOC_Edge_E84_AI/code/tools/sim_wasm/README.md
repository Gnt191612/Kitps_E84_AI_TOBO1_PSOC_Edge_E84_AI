# 3D 实时仿真

`tools/sim_3d.html` 的“实时仿真”把真实的 H7 固件放在浏览器里运行，外部世界由模型提供。不接硬件就能拖动人、换场景、拔线，看固件的反应。

| 部分 | 真实程度 | 文件 |
|---|---|---|
| H7 调度、雷达背景和变化检测、云台、目标管理、融合、复锁、接力 | **真实固件源码**，编译成 WebAssembly | `sim_host.c` + `STM32H7/` → `sim_3d/firmware_wasm.js` |
| ESP32 闭环控制量、丢失判定 | 照抄 `ESP32_ov2640/tracking`，测试核对常数 | `sim_3d/world.js` |
| ESP32 图像跟踪 | 模型：目标在视野内且没被挡住就跟得上，加噪声和随机跟丢 | `sim_3d/world.js` |
| 84E 识别 | 模型：准确率取模型评估结果（仅 AI 生成图，未实拍），只算画面里最靠近中心的物体 | `sim_3d/world.js` |
| 超声波、舵机速度、串口、房间 | 模型：参数是按数据手册和经验估的，**都没有实测** | `sim_3d/world.js` |

所以它适合查逻辑问题、试参数方向、排练和判断接错线的现象。发现时间、误差这些数字依赖模型参数，不能当实物性能写进报告。上板实测后，把量到的值填进“仿真”页的参数，模型才会接近实物。

## 没有建模的部分

- 真实摄像头画面、光照、图像跟踪算法本身
- 俯仰方向（只算水平）
- 串口帧的打包解析（`tests/test_protocol.c` 单独测），串口电平问题
- 供电压降、舵机抖动和负载变化
- 84E 和 ESP32 的固件没有运行，只有 H7 是真实代码

## 改了 H7 固件之后

3D 仿真里跑的是编译好的固件，要重新生成：

```bash
python build_firmware.py
```

需要 [wasi-sdk](https://github.com/WebAssembly/wasi-sdk/releases)，解压到仓库根目录的 `.tools/wasi-sdk-13.0`，或用环境变量 `WASI_SDK_PATH` 指定。只有改固件的人需要它，使用软件不需要。

## 测试

```bash
node test_live_sim.js
```

检查内嵌固件是否为当前源码、模型常数是否和 ESP32 固件一致、完整流程、接线故障，并打印跟踪速度表。不需要编译器（检查固件时需要 Python）。

`node try_scene.js intrude 60 typical 1 -v` 可以在命令行跑一个场景并打印事件。

## 仿真发现的固件问题（2026-11-05，未改固件）

运行测试时会标为“已知问题”，修好后测试会提示改成正式检查。

1. **云台跟不上正常走路。** 理想传感器下，2.4 m 处横穿：60 cm/s 能跟住，80 cm/s 以上就丢。`closed_loop.c` 的 Kp=0.5 乘 H7 的换算系数（2°/400），每帧只修正约 1.5% 的偏差。`tests/test_h7_demo_flow.c` 的替身用的是每帧 30%，比真实代码高约 20 倍，所以以前的测试没有发现。把“ESP32 闭环增益”调到 5 倍后，150 cm/s 也能跟住。实物增益还要上板确认，调太大可能振荡，这里没有建模。
2. **主跟踪板无回应时不换板。** H7 派 A 板主跟踪、B 板辅助，A 板命令线断或死机时，B 板看得见人，目标却一直锁不上。
3. **空房间偶尔出现假候选。** 斜对墙面时回波时有时无、距离随角度变化快，同一格两次测距可差 30 cm 以上。典型参数下 10 分钟约 3 个，再遇到 84E 误报就会去跟不存在的目标。波束和噪声都是估计值，需要实测确认。
4. **单帧跟丢就算丢失。** ESP32 第一帧没跟上就上报 lost，H7 立刻转入丢失流程。按估计的 0.5% 单帧跟丢率，70 秒内约丢失十几次，大多能很快复锁。实际跟丢率要实测。

# 超声波雷达前端

HC-SR04 由 270° 舵机带动往复扫描。超声波本身分不清墙和人，所以这里不把“测到东西”当目标，而是把**“比没人时明显变近”**的位置当目标。

## 工作流程

1. **非阻塞测距**（`radar_driver.c`）：`Radar_Trigger()` 只发 TRIG 脉冲就返回，回波由 TIM3_CH1 输入捕获中断记录，主循环用 `Radar_Poll()` 取结果，不再忙等。每 70 ms 触发一次。
2. **不动 TIM3 计数器**：TIM3 的 CH2/3/4 同时输出三路云台舵机 PWM。原来每次测距都把计数器清零，会让这三路舵机抖动。现在用两次捕获值之差，加上毫秒时基算出跨了几个 20 ms 周期，得到脉宽。
3. **超量程不算点**：没有回波或超过 4 m 时，记为“该方向量程内没有物体”，不再钳位成 400 cm 的假目标。
4. **角度分格**（`radar_map.c`）：舵机 0°~270° 每 5° 一格。每次测量记入“触发时与回波时舵机角的平均值”所在的格。
5. **背景学习**：上电后每格先采 3 次，取中值作为背景距离。全部学好后串口打印 `Radar background learned`，之后才开始报目标。**上电后约 30 s 内扫描范围里不要有人。**
6. **变化检测**：某格测得距离比背景近 30 cm 以上，记为“变化格”。相邻且距离相差小于 50 cm 的变化格合成一个候选；只有一格时，要求该格连续两次测量都成立。
7. **背景更新**：没有变化的格，背景以 0.05 的系数缓慢跟随环境。84E 判为“不是人”的候选，会把该方位 ±10° 内的当前距离直接并入背景，以后不再报。

调度器（`Core/scheduler.c` 的 `Process_Radar`）每轮主循环都调用雷达，不再只在“雷达扫描”阶段运行。原先锁定第一个目标后雷达就停了，发现不了第二个目标。落在已跟踪目标 ±20°、±80 cm 内的候选视为同一人，不会再分配第二块 ESP32 去跟它。

## 需要上板整定的参数

| 参数 | 位置 | 默认值 | 说明 |
|---|---|---|---|
| `RADAR_BIN_DEG` | radar_map.h | 5° | 格越小角度越细，但每格采样更少 |
| `RADAR_BG_LEARN_SAMPLES` | radar_map.h | 3 | 学习背景的采样次数 |
| `RADAR_CHANGE_CM` | radar_map.h | 30 cm | 太小会被噪声误触发，太大会漏掉靠墙站的人 |
| `RADAR_BG_ALPHA` | radar_map.h | 0.05 | 背景跟随环境的速度 |
| `RADAR_CHANGE_TTL_MS` | radar_map.h | 8000 ms | 应略大于同一格两次被扫到的最长间隔（每段扫描 3 s） |
| `RADAR_PING_INTERVAL_MS` | radar_process.h | 70 ms | 不得小于 60 ms，否则前后两次超声波串扰 |
| `SERVO_SWEEP_LEG_MS` | Drivers/servo.h | 3000 ms | 扫描越慢，每格采样越多 |
| `RADAR_SAME_TARGET_DEG/CM` | Core/scheduler.c | 20° / 80 cm | 判断“雷达看到的是已跟踪的那个人”的范围 |

## 尚未验证

- 背景学习和变化检测在真实房间里的效果、阈值是否合适
- 舵机实际角度会滞后于指令角度，滞后量需要实测补偿
- 实际角度分辨率（HC-SR04 波束约 15°~30°）
- 去掉清零计数器后舵机抖动是否消失

# 中期答辩演示手册

演示完整走一遍“发现 → 确认 → 跟踪 → 接力 → 复锁 → 排除静物 → 停止”。全程用监控界面展示，不需要额外安装软件。

> **现状：** 下面的流程只在电脑上用仿真验证过，**还没有在实物上跑通**。答辩前必须按第 1 节上板排练。仿真画面右上角有“仿真回放：不是实物数据”标识，展示时请如实说明，不要当作实测结果。

## 1. 答辩前的准备

按顺序做，每一步通过后再做下一步：

1. **H7 单独上电。** 接 USB-TTL（PC10→RX、PC11←TX、GND），用监控界面连接串口，点“查询状态”应有回复。
2. **雷达和雷达舵机。** 舵机单独供电并与 H7 共地；先标定脉宽。范围内不要有人，等界面显示“已学好”（约 20~40 s），再看墙壁轮廓是否合理。
3. **ESP32 单独上电。** 用控制台确认摄像头和帧率，再接 H7 串口。
4. **84E 单独上电。** 确认 `$I` 输出和推理结果；84E 与 H7 之间必须加 1.8 V ↔ 3.3 V 电平转换。
5. **三路云台。** 确认 `config_mount.h` 的 `MOUNT_CAMx_PAN_OFFSET` 与实际安装朝向一致，否则界面和实际方向会对不上。
6. **在答辩场地现场学习背景，并至少完整排练两遍。**

接线见 [WIRING.md](WIRING.md)，H7 板的 TF 卡槽、LCD 和 CAMERA 座不要插任何东西。

## 2. 打开监控界面

用 Edge 或 Chrome 打开 [tools/demo_monitor.html](tools/demo_monitor.html)，点“连接串口”，选择 USB-TTL 对应的串口（921600）。

| 按钮 | 作用 |
|---|---|
| 停止 / 恢复 | 所有云台回初始朝向并暂停；恢复后重新发现目标，背景保留 |
| 重新学习背景 | 换场地或搬动物品后使用，不必重启。学习期间范围内不要有人 |
| 查询状态 | 打印目标、跟踪板和各链路通信统计 |
| 保存日志 / 导出轨迹 | 保存本次原始日志，或把目标轨迹导出为 CSV |

保存的日志可以用 `python tools/exp_stats.py 日志文件` 统计指标。

## 3. 演示流程

| 步骤 | 操作 | 界面上应看到 | 可以讲的要点 |
|---|---|---|---|
| 1 | 上电，范围内无人 | 雷达扫描，轮廓逐渐出现，显示“已学好” | 系统先记住环境，只关注变化，所以能区分墙和人 |
| 2 | A 走进扫描范围后站定 | 候选 → 84E 判定是人 → 一块板锁定 | 雷达负责发现，NPU 确认，ESP32 跟踪，图像不上传 |
| 3 | A 横向走过正前方 | 一块板转到边界，另一块接手 | 边界接力，两块板协作 |
| 4 | B 从另一侧走入 | 第二个目标出现，由空闲的板跟踪 | 多目标资源分配 |
| 5 | 用纸板短暂挡住 B（约 1 s） | 显示跟丢，随后复锁 | 跟丢后结合历史轨迹预判复锁 |
| 6 | 在远离两人的位置放椅子或纸箱 | 候选 → 判定不是人 → 释放，之后不再报 | 误报的物体并入背景 |
| 7 | 点“停止” | 目标清空，云台全部回初始朝向 | 安全停机 |

**动作要慢。** 雷达一轮扫描约 12 s，新出现的目标可能要等几秒才被发现，这是正常现象。人站定后更容易被发现，走动时不要超过云台跟随速度。

## 4. 现场应急

| 情况 | 处理 |
|---|---|
| 没有人也一直报目标 | 让所有人离开，点“重新学习背景” |
| 人站着不被发现 | 确认距离小于 3.7 m，并且不要贴墙（需比背景近 30 cm 以上） |
| 判定结果不准 | 模型未达设计指标，真实画面精度未知。把人站近一些、光线好一些；如实说明这是当前问题和下一步工作 |
| 某块板不跟踪 | 点“查询状态”看角色和通信统计；确认该板的串口线和供电 |
| 舵机抖动或电脑串口断开 | 点“停止”，检查舵机电源是否与控制板分开、是否共地 |
| 实物无法演示 | 点“回放日志”，选择 [tools/demo_sim.log](tools/demo_sim.log)，并明确说明这是仿真 |

## 5. 不要这样说

- 不要把回放或仿真结果说成实测；仿真中的时延不代表实物性能。
- 目前模型的精度数字来自 AI 生成图像（约 92.5% / 误报 7.6%），未达到设计指标，也不代表真实画面。
- 仿真中“发现→锁定”约 1.1~1.6 s，超过 500 ms 的设计目标，主要花在云台转动上。如果被问到，如实说明并作为后续优化项。
- 声光报警和通知推送尚未实现，局域网切换和语音播报也还没有接入真实功能。

## 6. 更新仿真日志

运行 `code/tests` 的测试后，整机流程仿真会生成 `tests/build/demo_flow.log`。如果改了调度或雷达代码，用它覆盖 `tools/demo_sim.log`。

# 项目描述 — 嵌入式多板协作目标检测跟踪系统

## 参赛信息

- **赛事**: 全国嵌入式芯片竞赛，英飞凌赛道
- **AI识别板**: Infineon KIT_PSE84_AI 开发评估套件（PSE846GPS2DBZC4A，Cortex-M55 + Cortex-M33 + Ethos-U55 NPU，OV7675 DVP）
- **主控板**: 第三方 STM32H743ZIT6 开发板（Arm Cortex-M7；替代早期方案中的 STM32F407）
- **视觉板**: 双 GOOUUU ESP32-S3-CAM N16R8（16 MB Flash + 8 MB PSRAM）+ OV2640（跟踪 + 辅助定位）
- **舵机**: 水平轴为 SG90 9G 270°位置舵机，俯仰轴为 SG90 9G 180°位置舵机；均非360°连续旋转舵机
- **感知模块**: HC-SR04 超声波雷达

## 系统架构

三块板协作，主控 H7 统一调度：

```
┌──────────┐  ┌──────────┐  ┌───────────┐
│ HC-SR04  │  │ PSE84E   │  │ ESP32×2  │
│ 雷达扫描  │  │ NPU 识别  │  │ 视觉跟踪  │
│ → DBSCAN │  │ → 全图   │  │ → PID 云台│
│ → 聚类   │  │ → 推理   │  │ → 闭环控 │
│ → 候选   │  │ → 置信度  │  │ → 复锁   │
└────┬─────┘  └────┬─────┘  └──────┬────┘
     └──────────────┼──────────────┘
                    ▼
          ┌───────────────────┐
          │   STM32H743ZIT6   │
          │   (总控调度器)      │
          │   雷达→84E→ESP32  │
          │   目标管理/融合    │
          │   卡尔曼滤波       │
          │   自闭环/复锁      │
          │   语音播报/Ethernet │
          └───────────────────┘
```

## 工作流程

### Phase 1 — 雷达扫描与目标发现
HC-SR04 由270°横向位置舵机带动，按“正前135°→左端0°→正前135°→右端270°→正前135°”周期扫描，采集回波点云 → 限幅滤波 + 滑动平均 → DBSCAN 聚类 → 筛选>0.2m 的候选目标。系统启动时84E和两块ESP32均保持各自初始朝向，只有雷达周期扫描。

### Phase 2 — NPU 识别（KIT_PSE84_AI，简称84E）
H7 将候选目标的方位角、距离等信息通过 UART 发给 KIT_PSE84_AI：
1. H7先控制PSE84E云台指向目标方向，到位后再向PSE84E发送识别命令；84E空闲时保持当前位置
2. 采集 160×120 灰度全图
3. **全图归一化后直接送入 Ethos-U55 NPU 推理**（使用 Infineon 官方 ML 工具链训练的模型）
4. 读取二分类输出（0=背景, 1=人体），获取置信度
5. 结合卡尔曼滤波进行目标轨迹平滑
6. 结果回传 H7

> **NPU 识别方案**：全图直接推理 + Edge Impulse / ModusToolbox AI 工具链训练。
> 采集各场景照片 → 标注（人/背景）→ 训练 int8 量化模型 → 部署到 NPU。
> 雷达负责定位（角度+距离），NPU 只需做是否为人体的二元确认。

### Phase 3 — 视觉跟踪（双 GOOUUU ESP32-S3-CAM N16R8 + OV2640）
识别成功且目标在 10m 内 → H7 向 ESP32 发跟踪指令：
1. ESP32 状态机：IDLE → TRACKING → LOST → RELOCKING → TRACKING/IDLE
2. 图像采集 → 灰度化 → 在全图均匀选取 3×2 网格中高梯度区域 → 搜索窗穷举匹配
3. ESP32计算PID控制量并回传H7，由H7控制270°横向、180°纵向位置舵机
4. 均值滤波 + 卡尔曼滤波 → 速度估计 + 位置预测
5. 跟踪结果回传 H7（含目标id、坐标、Pan/Tilt PID控制量和丢失状态）
6. 若连续 5 帧丢失 → 自动尝试复锁（最多 3 次）→ 仍失败则调用 84E 辅助扫描

### Phase 4 — 资源优化策略
- **单目标时**：两个 ESP32 互相辅助定位，84E 空闲可查找额外目标
- **双目标时**：每个 ESP32 跟踪一个目标
- **边界接力**：当前ESP32横向接近15°或255°时，H7预置另一块ESP32；若84E空闲则同时辅助识别，新ESP32稳定锁定后释放原ESP32并令其回到135°初始朝向
- **第三目标出现**：外部操控端和局域网目标切换暂缓实现，当前版本由H7本地自主调度

### Phase 5 — 丢失与复锁
- 跟踪丢失 → ESP32 自动扩大搜索窗口匹配
- 若无法复锁 → 释放进程 → H7 重新调用 84E 扫描那一区域
- 暂时跟丢期间按最近运动趋势继续预测

## 通信协议

三方帧格式统一（AA 55 XOR 校验）：

| 链路 | 类型 | 内容 |
|------|------|------|
| H7→84E | 0x01 | 指令+角度+宽度+距离范围 |
| 84E→H7 | 0x02 | 目标 id+置信度+坐标+距离 |
| H7→ESP32 | 0x02 | 命令+目标 id+参数 |
| ESP32→H7 | 0x02 | 目标 id+坐标+Pan/Tilt PID控制量+丢失标志 |

所有 UART 均为 115200bps，ISR 使用环形缓冲区消除竞态。

## 算法设计

### NPU 识别（KIT_PSE84_AI + OV7675 DVP）— 全图推理
- 使用 Infineon 官方 ML 工具链（Edge Impulse / ModusToolbox AI）在 160×120 灰度图像上训练二分类模型
- 推理：采集图像 → 全图归一化（/255.0）→ NPU_INVOKE → 读置信度
- 相比旧方案（区块细扫+梯度特征+三次推理），代码量减少 80%，发挥 Ethos-U55 设计能力

### 视觉跟踪（ESP32）
- 梯度特征：Sobel 算子计算搜索窗内梯度强度
- 滤波：均值滤波 + 卡尔曼滤波（4×4 矩阵完整实现）
- 预测：低通滤波速度估计 + 位置预测
- 云台 PID：Kp=0.5, Ki=0.01, Kd=0.1（可根据现场整定）

### 雷达处理（STM32H7）
- DBSCAN 聚类（eps=0.5m, minPts=3）
- 限幅滤波 + 滑动平均消除噪声
- 卡尔曼滤波融合 84E 和 ESP32 的多源数据

## 数据记录与评估

系统在运行过程中记录以下数据用于性能评估：
- **84E 推理延迟**：从 H7 发指令到收到结果的延迟
- **ESP32 跟踪帧率**：采集→处理→回传的周期
- **识别错误率**：NPU 的误报/漏报统计
- **跟丢率**：跟踪过程中丢失目标的频率
- **算法性能对比**：可针对不同参数组合记录延迟和准确率

## 硬件接线要点

> 详细见 `WIRING.md`（杜邦线速查表）

- KIT_PSE84_AI ↔ H7 USART1（具体可用接口与1.8V/3.3V电平转换待按官方原理图确认）
- H7 USART2 ↔ ESP32-A UART1
- H7 USART3 ↔ ESP32-B UART1
- 7 路舵机全部由 H7 PWM 直控（TIM2/TIM3）
- 4路横向舵机均为270°位置舵机，计划初始朝向135°；3路纵向舵机均为180°位置舵机，计划初始朝向90°，安全脉宽需按实物校准
- HC-SR04 TRIG=PC0, ECHO=PC6（需分压 5V→3.3V）
- ESP32 和舵机**必须独立外部供电**
